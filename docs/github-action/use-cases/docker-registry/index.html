Docker Registry Access

This guide shows how to configure Bullfrog to allow pulling Docker images from various registries while blocking other outbound connections.

Docker Hub​

To pull images from Docker Hub, you need to allow several Docker-related domains:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      *.docker.com
      docker.io
      *.docker.io

Full Example:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
        with:
          egress-policy: block
          allowed-domains: |
            *.docker.com
            docker.io
            *.docker.io

      - name: Pull Docker image
        run: docker pull nginx:latest

      - name: Run container
        run: docker run --rm nginx:latest nginx -v

Why Multiple Domains?​

Docker Hub uses multiple domains for different purposes:

  • docker.io - Main registry endpoint
  • *.docker.io - Registry mirrors and CDN (e.g., registry-1.docker.io, production.cloudflare.docker.com)
  • *.docker.com - Authentication and metadata (e.g., auth.docker.io, registry.docker.com)

GitHub Container Registry (ghcr.io)​

To pull images from GitHub Container Registry:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      ghcr.io
      *.ghcr.io
      github.com
      *.github.com

Example:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      ghcr.io
      *.ghcr.io
      github.com
      *.github.com

- name: Login to GitHub Container Registry
  run: echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin

- name: Pull image
  run: docker pull ghcr.io/owner/image:latest

AWS Elastic Container Registry (ECR)​

For AWS ECR:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      *.amazonaws.com
      *.ecr.*.amazonaws.com

With AWS CLI:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      *.amazonaws.com

- name: Login to ECR
  run: |
    aws ecr get-login-password --region us-east-1 | \
    docker login --username AWS --password-stdin ${{ secrets.ECR_REGISTRY }}

- name: Pull image
  run: docker pull ${{ secrets.ECR_REGISTRY }}/my-image:latest

Google Container Registry (GCR)​

For GCR and Google Artifact Registry:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      gcr.io
      *.gcr.io
      *.googleapis.com
      *.google.com

Azure Container Registry (ACR)​

For Azure ACR:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      *.azurecr.io
      *.azure.com
      *.microsoft.com

Multiple Registries​

If you need to pull from multiple registries, combine the required domains:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      # Docker Hub
      *.docker.com
      docker.io
      *.docker.io
      # GitHub Container Registry
      ghcr.io
      *.ghcr.io
      github.com
      *.github.com
      # AWS ECR
      *.amazonaws.com

Building Docker Images​

If your workflow builds Docker images that pull base images:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
        with:
          egress-policy: block
          allowed-domains: |
            *.docker.com
            docker.io
            *.docker.io

      - uses: actions/checkout@v4

      - name: Build Docker image
        run: |
          # Dockerfile: FROM node:18
          docker build -t myapp:latest .

The docker build command will pull the node:18 base image from Docker Hub.

Private Registries​

For private Docker registries accessed by IP:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-ips: |
      192.168.1.100
    dns-policy: any

Or by domain:

- uses: bullfrogsec/bullfrog@1831f79cce8ad602eef14d2163873f27081ebfb3 # v0.8.4
  with:
    egress-policy: block
    allowed-domains: |
      registry.mycompany.com
      *.mycompany.com

Troubleshooting​

Error: "unauthorized: authentication required"​

This usually means authentication domains are blocked. Ensure you've allowed:

  • For Docker Hub: *.docker.com, auth.docker.io
  • For GHCR: github.com, *.github.com

Error: "connection refused" or "timeout"​

Check that you've allowed all necessary domains:

  1. Run in audit mode first to discover all connections
  2. Check the workflow summary for the full list of domains
  3. Add any missing domains to your allow list

Image pull is slow or fails intermittently​

Docker registries use CDNs and mirrors. Make sure to use wildcard domains:

  • *.docker.io (not just docker.io)
  • *.docker.com (not just docker.com)
